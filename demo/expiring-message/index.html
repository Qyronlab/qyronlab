A message that cannot be copied — and expires

On an ordinary message bus a message lasts forever and can be copied. A quantum network carries a different kind of message: an entangled pair. It cannot be copied, it can be used only once, and it loses quality while it waits. This page shows such a message with real data, and lets your browser check every claim itself.

1. How long does the pair stay good?

The points are measured: one entangled pair on IBM's ibm_kingston processor (qubits 32 and 33), 21 October 2026. The curves are the prediction — a model written down and sealed by its fingerprint before the measurement. With one echo pulse (teal) the pair lives about four times longer.

—predicted pair fidelity F
—usable if F − 3σ ≥ 0.5
—lifetime in this mode

Above F = 0.5 the pair is still entangled, and sending a quantum state over it beats every classical method. The margin 3σ is the counting error of the measurement.

2. Send the message, then try to cheat

Each use of a pair produces a receipt: which pair, how long it waited, and whether it was still good. Every event also goes into a ledger whose rows are signed and chained. Both are signed twice — with today's Ed25519 and with the post-quantum ML-DSA-65 — by a key your browser has just made. The checker below trusts nothing the issuer says: it recomputes the fidelity from the sealed model and reads the ledger itself.

    3. What this is, and what it is not

    RealThe measured points, the sealed model (it matched 9 of 11 raw points and 11 of 11 echo points within 0.03), the rule, the signatures, the chained ledger and the checks — all run here, in your browser.
    SimulatedThe pairs you create on this page: their quality comes from the sealed model, not from a new measurement.
    LimitsOne processor, one pair, one day. The pair waits inside a chip, so it lives for microseconds; a network memory would live longer — the receipts and the ledger would stay the same, only the curve would change. The signing key is a throwaway key made in your browser.
